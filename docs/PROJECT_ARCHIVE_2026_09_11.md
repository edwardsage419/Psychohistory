# Psychohistory Archive Decision

Decision date: 2026-09-11

Status: ACCEPTED OWNER DECISION

## Decision

Psychohistory is placed into an archived, inactive preservation state.

The project remains a recoverable research asset and historical predecessor to a future clean project focused on forecast trust, prospective evidence, outcome resolution, evaluation, failure analysis, and model audit infrastructure.

The strategic work accepted on 2026-09-11 remains valid as design provenance. It will be transferred selectively into the new project as methodological input rather than continued here as active implementation.

## Archive status

Repository status after this decision: `ARCHIVED_INACTIVE`.

There is no active development task in Psychohistory.

`docs/NEXT_ACCEPTED_TASK.md` is superseded as an execution authorization. Its Forecast Trust Core design remains useful migration material for the new project.

The archive baseline is the `main` commit that contains this decision and the associated archive state updates.

## Execution guard

While status remains `ARCHIVED_INACTIVE`, no substantive research or product development is authorized merely because a task, roadmap, design, issue, report, or prior chat exists.

Do not begin or resume:

1. Forecast Trust Core implementation in this repository
2. Forecast Ledger Genesis
3. GKG recovery
4. independent semantic review
5. indicator promotion
6. new source family integration
7. production forecasting
8. outcome scoring or calibration
9. frontend or API work
10. scheduled production workflows
11. new recurring infrastructure

Reading, auditing, reproducing accepted results, exporting migration material, and inspecting Git history are allowed.

Any modification beyond archive metadata, critical preservation repair, or explicitly authorized reproducibility maintenance requires a new owner decision.

## Preservation boundary

The archive operation must preserve the accepted scientific record exactly in meaning.

Preserve:

1. all committed study artifacts and evidence
2. the frozen GKG samples and identity bindings
3. accepted Phase reports and protocols
4. human review artifacts and their provenance
5. evidence sufficiency classifications
6. failed, unresolved, mismatched, and unavailable states
7. scientific invariants
8. accepted forecast architecture and point in time methodology documents
9. Git history and prior strategic decisions

The archive decision resolves no scientific uncertainty and changes no historical result.

## Relationship to the future project

The future project should start with a clean repository and a new Genesis.

It may import or adapt methodological concepts from Psychohistory, including:

1. scientific invariants
2. point in time data and vintage rules
3. target and resolution contracts
4. forecast method and run attempt provenance
5. immutable issuance and correction rules
6. prospective external time anchoring
7. frozen evaluation cohorts and denominator accounting
8. baseline parity
9. failure corpus concepts
10. near zero cost operating discipline

Historical Psychohistory research artifacts must not silently become native evidence of the new project.

The migration contract is recorded in `docs/NEW_PROJECT_MIGRATION_PACKET.md`.

## Reactivation rule

Psychohistory may be reactivated only through an explicit owner decision that states why work belongs in this historical repository rather than the successor project.

A future request to inspect, cite, reproduce, or reuse Psychohistory does not itself reactivate the project.

## Recommended use of this repository

Treat Psychohistory as:

1. a preserved research predecessor
2. a source of audited methodological lessons
3. a case study in measurement validity and evidence recovery
4. a provenance source for selected successor project design concepts

Do not use it as the default implementation workspace for the successor forecast trust project.
