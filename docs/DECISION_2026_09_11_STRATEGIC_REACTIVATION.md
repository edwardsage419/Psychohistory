# Strategic Reactivation Decision

Decision date: 2026-09-11

Status: ACCEPTED OWNER DECISION

## Decision

Psychohistory is reactivated as an active long horizon research and product project.

The strategic north star is revised from a broad world state forecasting application toward an independent evidence layer for machine forecasting.

The project will prioritize, in order of durable strategic value:

1. a prospective, append only Forecast Ledger with strong point in time provenance
2. reproducible forecast, target, resolution, and evaluation contracts
3. a longitudinal Forecast Failure Corpus derived from resolved forecasts
4. model neutral trust and audit capabilities that compare forecasting methods under common evidence rules
5. low maintenance public exports and later institutional interfaces

The project may still research social indicators, macro state representations, and individual source families. Those activities are supporting research tracks rather than a global prerequisite for building the forecast evidence infrastructure.

## Strategic rationale

The project is maintained by one operator under a zero or near zero recurring cost constraint. It should avoid competition on compute scale, real time data breadth, community size, prediction market liquidity, model training scale, and feature volume.

The durable moat should come from assets that compound with elapsed time and disciplined operation:

* prospective records that existed before outcomes were known
* immutable and replayable evidence chains
* long lived method and schema continuity
* explicit failure and unresolved records
* accumulated error and calibration history
* cross model comparability under stable protocols
* independence from any single model provider or source family

A competitor can copy software later. It cannot recreate a prospective record that should have existed years earlier.

Current external competition reinforces this choice. Forecasting platforms and research benchmarks already have large question sets, human baselines, AI model leaderboards, and active bot competitions. Psychohistory therefore should not pursue another general forecasting platform or another frontier model leaderboard as its primary identity.

## Product position

Working strategic position:

Psychohistory is an independent evidence layer for machine forecasting.

The core product question is:

Which forecasts deserve trust, based on what was actually known, issued, resolved, and measured at the time?

The project should eventually make it possible to verify a forecast lineage from target definition and information cutoff through issuance, resolution, scoring, calibration, and failure analysis.

## Program tracks

### Track A: Forecast Trust Core

This is the primary engineering track.

It includes:

* target definition contracts
* resolution rule contracts
* point in time evidence and feature snapshots
* forecast method identity and versioning
* append only issuance
* append only corrections
* independent resolution records
* deterministic verification
* frozen evaluation cohort manifests

Track A may advance before broad multi source state construction exists. It must remain scientifically explicit about the source and method used by each forecast.

### Track B: Prospective Forecast Ledger

This is the primary time compounding asset.

After the minimum Trust Core is accepted, Psychohistory should begin a small, curated, prospective forecast program using targets that have objective resolution rules and low cost public evidence.

Early forecasts should emphasize quality of provenance over question volume. Transparent baselines should be included as first class forecast methods.

Formal ledger history must never be backfilled with retrospective forecasts presented as contemporaneous records.

### Track C: Forecast Failure Corpus

As outcomes accumulate, each resolved forecast should produce structured failure evidence where applicable.

The corpus should preserve at least:

* forecast and method identity
* information set identity
* uncertainty
* outcome and resolution provenance
* score and baseline comparison
* error class
* known data, method, regime, semantic, or resolution limitations
* correction history

The corpus is intended to become a distinctive longitudinal research asset rather than a collection of selected success stories.

### Track D: Trust and Audit Layer

After enough prospective evidence exists, Psychohistory should compare external and internal forecasting methods under common contracts.

Potential subjects include statistical baselines, econometric methods, language models, agentic forecasting systems, expert estimates, public consensus estimates, and market implied probabilities where legally and methodologically appropriate.

The system should remain model neutral. Model progress should increase the value of the evaluation layer rather than obsolete the project.

### Track E: Public and Commercial Interfaces

Productization follows evidence accumulation.

Preferred sequence:

1. static or low maintenance public ledger views and exports
2. machine readable data and verification interfaces
3. professional research exports and model comparison reports
4. private institutional forecast audits and custom benchmark programs
5. paid API or hosted services only when demand justifies recurring operating cost

The project should prefer a small number of high value institutional users over a high support consumer subscription product.

### Track M: Measurement Research

Existing indicator and source validation work belongs here.

GKG remains a preserved experimental media attention candidate. Its accepted evidence, frozen samples, protocols, human judgments, failures, and unresolved states remain authoritative historical research artifacts.

GKG recovery no longer controls the global project queue. Additional GKG recovery requires a new bounded decision showing that the expected scientific information gain justifies the maintenance effort.

A new source family may be studied when it directly supports a forecast target, a trust evaluation, or a clearly defined measurement question.

## Dependency rule

The old interpretation that forecasting must wait for a complete multi source world state model is retired.

A formal forecast may enter the experimental prospective ledger when all dependencies required for that forecast are individually defensible, including target semantics, information cutoff, evidence provenance, method identity, resolution rule, and issuance integrity.

A forecast that depends on an unvalidated indicator must remain blocked or explicitly experimental according to the applicable protocol. One unresolved measurement candidate must not globally block unrelated forecast targets with independent evidence foundations.

## Non goals

Psychohistory should not optimize for:

* becoming a large forecasting community
* operating a prediction market
* training a frontier foundation model
* high frequency trading or real time market prediction
* broad real time news coverage
* a single opaque world risk score
* a feature rich dashboard before the evidence layer is useful
* large recurring infrastructure commitments

## Resource rule

The zero or near zero recurring cost constraint remains a first class architectural requirement.

Prefer local execution, standard library or lightweight open source dependencies, Git and content addressed artifacts, SQLite or DuckDB or Parquet when useful, static publication, and bounded scheduled work.

Paid infrastructure requires evidence that it materially improves reliability, reproducibility, product value, or revenue capacity.

## Strategic acceptance test for future work

A proposed core task should materially improve at least one of these assets:

* provenance integrity
* prospective longitudinal history
* failure knowledge
* trust or comparison value
* low cost durability

Tasks that improve none of these require explicit justification before entering the core roadmap.

## Immediate consequence

The project status changes from PAUSED to ACTIVE STRATEGIC REALIGNMENT.

The frozen deterministic GKG recovery target manifest remains preserved in Git history and as a valid historical task design, but it is superseded as the active next task.

The next bounded task will define the minimum Forecast Ledger Core contracts and verifier needed to support a future Forecast Ledger Genesis without issuing real forecasts yet.

No accepted GKG evidence is rewritten by this decision.
